# button
-　特定の操作を開始したり、システムの処理を実行するパーツ
- あらゆる画面で利用しユーザーの意思決定を行うため、アプリケーションの中で最も重要なパーツの1つ
## 原則
- 重要度によってデザインを変える
  - 主要な機能やユーザーの意思決定に関わるボタンは目立たせ、補助的な操作のボタンは控えめにすることで使い勝手が向上
  - アプリケーションで同じルールを徹底する
- ボタンの配置で優先度を調整する
  - ユーザーの視線誘導の観点から、画面上のどこにボタンを置くかで操作のしやすさは変わる。
  - 左上
    - 視線誘導の最初のため、目に入りやすい
    - 一方で、操作はしにくく、優先度の高いボタンはおかない
    - 戻るボタンなどを置く
  - 左下
    - 操作しにくい
    - 削除などのネガティブなボタンを置く
  - 右上
    - 操作しやすい
    - 画面全体に対する操作ボタンを置く
    - 何かを開始するボタンを置くのに適している
  - 右下
    - 操作しやすい
    - 視線誘導の最終地点のため、「保存」などの最終実行のボタンを置くのに適している
    - フローティングボタン
      - 主にモバイル
      - 常に親指で押しやすい位置に表示し続ける
      - 使用頻度が高い機能に用いる
- 非活性
  - 押せないことを表現
  - 半透明にするかグレーにする
  - 使えないボタンは押してからエラーにするのではなく、先に非活性にしておく
## ボタン定義の例
  - primary
    - 画面の最も重要な操作
    - 操作が確定する意思決定のボタンには必ず用いる
    - 保存・OK
  - Secondary
    - 主要な機能ではないボタン
    - 何かしらの操作を開始するときのボタン
    - 1ページの中に複数置くことができる
    - ネガティブなボタン
      - 「キャンセル」「クリア」等
      - 危険度高ければ、別途別種類のボタンを検討
  - Teritary
    - Secondaryボタンよりもより弱く見せたいボタンがある場合
    - 1ページの中に複数置くことができる
  - アイコンボタン
    - Secondaryボタンと同じ用途だが、画面レイアウト上にコンパクトに表示したい場合
    - PC画面ではオンマウス時に必ずツールチップでボタン名称を表示するようにする
