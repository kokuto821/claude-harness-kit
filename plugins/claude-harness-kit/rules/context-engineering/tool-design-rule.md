# ツール設計とコンテキスト効率のルール

ツールは、エージェントとその情報／行動空間との間の **契約**。ツールセットの設計は、そのままコンテキストの信頼できる保守・剪定に効く。よく設計されたコードベースの関数と同じ規律で設計する。

出典: `documents/reference/context-engineering/effective-context-engineering-for-ai-agents.md`（「効果的なコンテキストの解剖学」→ツール）。

## 1. 必要最小限のツールセットにする

- **肥大化を避ける**。あまりに多くの機能をカバーする、機能が重複する、どれを使うべきか判断が曖昧、といったツールセットは失敗モード。
- 判断基準：**ある状況で人間のエンジニアがどのツールを使うべきか断定できないなら、AI エージェントにそれ以上は期待できない**。選択が曖昧なら、まずツールセットを絞る／統合する。
- 実用最小限に絞ることは、長い対話にわたるコンテキストの、より信頼できる保守と剪定にもつながる（→ [[long-horizon-rule]]）。

## 2. トークン効率のよいツールにする

ツールは2つの意味で効率を推進する：**トークン効率のよい情報を返すこと**と、**効率的なエージェント挙動を促すこと**。

- **自己完結・エラー耐性・用途が極めて明確**。よく理解でき、機能の重複が最小のツールを作る。
- **入力パラメータは記述的で曖昧さがない**。モデルが本来持つ強みを活かせる形にする。
- **返り値もトークン効率よく**。生の巨大な出力をそのまま返さず、必要な情報に絞る（大量データはツール側で `head`/`tail`/クエリ等に寄せる。→ [[retrieval-rule]]）。
