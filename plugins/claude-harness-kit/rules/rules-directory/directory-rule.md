# rules ディレクトリ規約

## 目的

`rules/` には Claude が作業中に常に従うべき不変のガイドラインを置く。

| ここに置くもの | ここに置かないもの |
|---------------|-----------------|
| 命名規則・構造ルールなど普遍的な制約 | 特定タスクの手順（→ skills） |
| Claude の判断基準になるポリシー | 調査・参考資料（→ documents） |
| 繰り返し参照される設計上の決定 | 経験・知見メモ（→ knowledge） |

## ディレクトリ構造

**全ルールはサブディレクトリに入れる。`rules/` 直下にルールファイルを直置きしない。**

```
rules/
├── README.md                        ← rules/ の説明のみ。直下に置く唯一の例外
├── <topic>/
│   └── <short-name>-rule.md
└── ...
```

## 命名規則

| 対象 | 規則 | 例 |
|------|------|----|
| サブディレクトリ名 | kebab-case・トピックを表す名詞句 | `naming-conventions`, `repository-structure` |
| ルールファイル名 | `<短縮トピック>-rule.md` | `naming-rule.md`, `structure-rule.md` |

ディレクトリ名を短縮してファイル名にする（`naming-conventions/` → `naming-rule.md`）。

## 本文テンプレート

新規ルールは `plugins/claude-harness-kit/template/rules/RULE.md` を雛形にする。

構成は「原則（必須）→ 判断基準 → 適用手順 → やってはいけないこと → 背景 → 関連ルール」。不要な節は削除してよいが、**原則は省略しない**。ルールには *判断基準* だけを書き、事実・挙動の説明は `documents/reference/` に置く。

## スコープ（`paths:`）

冒頭 frontmatter の `paths:` で、そのルールを効かせるファイルを glob 指定できる。

| スコープ | 意味 | 向くルール |
|---------|------|-----------|
| `paths:` なし（frontmatter 省略） | 未スコープ。セッション開始時に常時ロード | 命名・構造など普遍的な制約 |
| `paths:` あり | 一致ファイルを触った時だけロード | 一部の層・拡張子にだけ効く規約 |

普遍的な制約は未スコープでよい。一部の対象にしか効かない規約は `paths:` でスコープし、無関係なセッションでのトークン消費を避ける。判断は [[selection-rule]] に従う。

## 新規作成 vs 既存更新

- **既存ルールと同じトピック** → 既存ファイルに追記する
- **新しいトピック** → 新サブディレクトリ＋新ファイルを作成する
- 1ディレクトリに複数ファイルを作らない（分割が必要なら別トピックとして切り出す）
