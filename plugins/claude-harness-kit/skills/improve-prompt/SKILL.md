# improve-prompt

## 概要

既存のプロンプト・スキル（SKILL.md）・サブエージェント定義を `rules/prompt-*` に照らして
見直し、的を絞った改善を抽出して適用するタスクスキル。言い換えの丸ごとリライトではなく、
失敗の診断に基づくピンポイントの編集を行う。レビュー（指摘のみ）は `prompt-review`。

## ルール

- 改善の進め方は [[improvement-rule]] (`rules/prompt-improvement/improvement-rule.md`) に従う。
- 構成要素の過不足は [[composition-rule]] (`rules/prompt-composition/composition-rule.md`) で確認する。
- 推論の足場の要否は [[scaffolding-rule]] (`rules/reasoning-scaffolding/scaffolding-rule.md`) で判断する。
- 敏感さ・過信・値の再掲は [[robustness-rule]] (`rules/prompt-robustness/robustness-rule.md`) に照らす。

## 手順

### 1. 対象と失敗例を把握する

改善対象のプロンプト／指示文を読む。可能なら、それが実際に外した入出力（失敗例）を集める。
失敗例が無ければ、どの挙動を良くしたいのかをユーザーに確認する。憶測だけで直さない。

### 2. 診断する

[[improvement-rule]] の手順に従い、「指示は正しくタスクを記述しているか」「欠落・曖昧・誤解を招く
箇所はどこか」を先に特定する。構成要素の欠落は [[composition-rule]] のチェックリストで洗う。
足場が必要か／過剰かは [[scaffolding-rule]] で判断する（単純タスクに CoT を足さない）。

### 3. 的を絞って改善する

診断した欠落・曖昧点をピンポイントで直す。全文リライトは避ける。規約の具体値は書き足さず
`rules/` を参照させる（[[robustness-rule]] のドリフト回避）。破壊的変更や意図不明箇所は
適用前にユーザーへ確認する。

### 4. 退行に備える

変更前後を比較できる形で示し、悪化時に戻せるようにする。可能なら失敗例で改善を確認する。

## 出力

- 診断結果（何が・なぜ効いていないか）。
- 改善点リスト（各項目に根拠ルールのパスを併記）。
- 適用後のプロンプト／指示文。確認が必要な変更は別途提示する。
