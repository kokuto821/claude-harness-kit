# frontend-code-review

## 概要

フロントエンドの変更を **コーディング規約 / テスト規約 / UIデザイン** の3観点で
横断レビューする統合オーケストレーター。各専門エージェントに委譲し、所見を1つに
統合して返す。**指摘までが責務**で、コードの改善・適用は行わない。

## 手順

### 1. レビュー対象を確定する

デフォルトは **git 変更差分**。`git status` と `git diff`（未コミット）＋
`git diff main...HEAD`（main との差分）で変更ファイルを把握する。
ユーザーがファイル・ディレクトリを明示した場合はそちらを優先する。

### 2. 変更を観点ごとに振り分ける

- 実装コード（`.ts` / `.tsx` / hooks / ユーティリティ）→ コーディング規約・UIデザイン
- テストコード（`*.test.ts` / `__tests__/`）→ テスト規約
- UI コンポーネント（JSX / Tailwind を含むファイル）→ UIデザイン

### 3. 専門エージェントへ委譲する（並行）

対象がある観点だけを起動する。独立しているため並行で投げてよい。

| 観点 | 委譲先 | 根拠ルール |
|------|--------|-----------|
| コーディング規約 | `frontend-coder` エージェント | `rules/coding-conventions/coding-rule.md` |
| テスト規約 | `frontend-tester` エージェント（テスト監査モード） | `rules/coding-conventions/test-rule.md` |
| UIデザイン | `ui-designer` エージェント | `rules/ui-design/`（索引経由） |

各エージェントには「レビュー対象ファイル／差分」と「指摘のみ・修正は適用しない」旨を渡す。

### 4. 所見を統合する

各エージェントの返り値を観点ラベル付きで束ね、重複を排除し、優先度
（Critical / Warning / Suggestion）で並べ替える。

## 出力

観点（コーディング規約 / テスト / UIデザイン）ごとにセクション分けし、各セクション内を
優先度順で示す。**修正の適用は行わない**（適用は `frontend-coding` / `frontend-tester` の
TDD実行 / `improve-ui-design` に委ねる旨を添える）。

- **Critical**: 動作・規約・UXを大きく損なう重大な問題
- **Warning**: 規約逸脱だが局所的なもの
- **Suggestion**: より規約に沿うための改善提案

各項目は `file:line` ／ 違反した規約（根拠ルールのパス）／ 問題点 ／ 修正の方向性 の形で示す。
全観点で違反がなければ「フロントエンド規約・UIデザイン準拠で問題なし」と明記する。
