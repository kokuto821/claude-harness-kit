# ui-review

## 概要

既存の UI 実装を `rules/ui-design/` のルールに照らしてレビューし、違反・逸脱を
Critical / Warning / Suggestion で指摘するタスクスキル。**指摘までが責務**で、
コードの改善・適用は行わない（適用まで行う場合は `improve-ui-design`）。

## 手順

### 1. レビュー範囲を決める

対象のコンポーネント・画面ファイルを特定する。差分が分かる場合は変更箇所を優先する。

### 2. 規模に応じてエージェント委譲を判断する

- **多数のファイルを横断する／本格的な監査**: `ui-designer` エージェントに委譲する
  （多ファイルを読み込み所見を構造化して返す役割）。
- **単一コンポーネント・少量の差分**: このスキル内で直接レビューする。

### 3. 索引から該当ルールを読む

`rules/ui-design/README.md`（索引）を読み、必要なルールだけを読む。全ファイルは読まない。

- 共通必読: `UI哲学.md` / `architecture/ui-architecture.md` /
  `styling-rule/color.md` / `space-and-radius.md` / `button-rule.md` /
  `improve-layout.md` / `improve-ui.md`
- 対象 UI に該当する `component/<分類>/<name>.md`

### 4. ルールと照合して指摘を抽出する

主な観点:

- 思想・分類（`UI哲学.md` の方針、button / edit / view と配置方針）
- 配色比率（70/25/5）・コントラスト 4.5:1（24px 以上は 3:1）
- 角丸（`rounded-lg`/`-full`/`-xl`、禁止 `rounded-md`/`-sm`/`-3xl`、入れ子は外側 +4px 以上）
- 余白による情報グルーピング・情報密度
- レイアウト（視線誘導、テキスト幅 ~600px、固定ヘッダー/フッター/スクロール分離）
- UX（フィードバック、破壊的操作の確認、空状態、文言、アニメーション 0.1〜0.3s）

## 出力

優先度ごとに整理して指摘を返す。**修正の適用は行わない**（依頼された場合は
`improve-ui-design` に委ねる旨を添える）。

- **Critical**: ユーザー体験・アクセシビリティを損なう重大な逸脱
- **Warning**: 規約逸脱だが局所的なもの
- **Suggestion**: より規約に沿うための改善提案

各項目は `file:line` ／ 違反した規約（根拠ルールのパス）／ 問題点 ／ 修正の方向性 の形で示す。
違反がなければ「ui-design ルール準拠で問題なし」と明記する。
