# tdd

## 概要

`tdd-rule` を唯一の根拠に、TDD サイクルの各フェーズを適切な産出者・レビュアーへ委譲する。
**フロントエンドは具象エージェント／スキルへ委譲**し、**具象エージェントが未定義のドメイン
（バックエンド等）はフロー統括のみ**を行う。指摘の適用はレビュー独立性に従い産出者が担う。

## ルール

- サイクル（Red-Green-Refactor-Commit）とコーディング標準は [[tdd-rule]]（`shared-rules/coding-conventions/tdd-rule.md`）に従う。フェーズを飛ばさず、現フェーズ（RED/GREEN/REFACTOR/COMMIT）を常に明示する。
- レビューと修正適用の分離は [[review-independence-rule]] に従う。Refactor のレビューも産出者と別エージェントが行い、適用は産出者に戻す。
- **産出者の単一責任**: Green（最小実装）は `frontend-coding` の責任。`frontend-tester` は Red のテスト実装のみを担い、実装コードの産出や Refactor の自己完結はさせない。
- **委譲の種別を区別する**: 「エージェント委譲」＝別コンテキストで隔離起動（中間結果でメインを汚さない）、「スキル起動」＝現行コンテキストで in-context 実行。両者を同じ語で括らない。Red のテスト産出は試行が多くメインを汚しやすいのでエージェントで隔離、Green の実装はステアリング可視性を優先して in-context とする。
- **反復上限**: 1機能あたり最大 3 サイクルを目安とする。3 周で緑にならない／未解決が残る場合は、サイクルを続けず、達成範囲と残課題を報告して人の判断を仰ぐ。これは対話の中で守る目安であり、ハーネスによる強制ではない（暴走はメインスレッドで可視・中断可能）。上限を確実に強制したい場合のみ、commit を捕捉する hook を別途用意する。
- **Refactor の停止条件**: レビュー→適用は 1 ラウンドで打ち切る。追加の指摘が残る場合は次サイクルの Refactor へ送る。
- **サイクルをまたぐ記憶**: 決定・未解決事項・次サイクルの狙いを、スクラッチパッドの `tdd-notes.md` に数行で退避し、次サイクル冒頭で読み直す（[[long-horizon-rule]]）。
- 規約の具体値は再掲せず、上記ルールを唯一の正として参照する（[[externalization-rule]]）。

## 手順

1. **対象ドメインを判定する** — frontend か、それ以外（具象エージェントが未定義のドメイン。バックエンド等）か。
   - frontend → 手順2〜5 のとおり具象エージェント／スキルへ委譲する。
   - それ以外 → Red フェーズは `test-coding` スキル（言語・ドメイン非依存。テスト観点洗い出し〜失敗するテストコード実装まで担う）へ委譲できる。それ以降（Green/Refactor/Commit）は **フロー統括のみ**にとどめ、各フェーズを宣言し `tdd-rule` の順序を守らせる。コード詳細・具体的な委譲先には関与しない。
2. **Red — 失敗するテストを書く**（frontend）
   - `frontend-tester` エージェントへ委譲（隔離起動）。「失敗するテストのみを実装し、実装コードは書かない」と明示する（`test-rule` 準拠）。テストが RED であることを確認する。
3. **Green — テストを通す最小実装**（frontend）
   - `frontend-coding` スキルを in-context 起動。テストは Red で用意済みのため実装のみ。テストを通す最小限にとどめ、余分な機能を足さない。全テストが GREEN になることを確認する。
4. **Refactor — レビュー主導の改善（緑を保つ）**（frontend）
   - コードは `frontend-code-reviewer`、テストは `frontend-test-reviewer` へ差分レビューを委譲（隔離起動・指摘のみ）。指摘を受け、産出者（`frontend-coding` / `frontend-tester`）が全テスト緑を維持したまま **1 ラウンド**適用する。残る指摘は次サイクルの Refactor へ送る。
5. **Commit — チェックポイントを記録**
   - 全テストが緑であることを最終確認（テスト実行で担保。[[review-independence-rule]]: 再検証も産出本人に委ねない）→ `git add` → 意味ある単一作業単位でコミットする。サイクルのノート退避（ルール「サイクルをまたぐ記憶」）を行う。
6. **次サイクルへ** — 機能が未完成で反復上限（ルール「反復上限」）に達していなければ、次サイクルへ戻る。上限に達したらルールに従い終了する。

## 出力

- 現フェーズ（RED/GREEN/REFACTOR/COMMIT）、委譲先と結果、テストの緑/赤状態、コミット単位、サイクル番号（例: 2 周目）。
- フロー統括のみのドメインは「コード詳細不関与」を一度明記し、フェーズ進行の骨子だけを返す。
