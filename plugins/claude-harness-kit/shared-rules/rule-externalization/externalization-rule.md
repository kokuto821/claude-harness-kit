# スキル・エージェントにおけるルール外部化の原則

## 原則

スキル（`skills/`）またはサブエージェント（`agents/`）を作成・編集する際、内部にルール・制約・判断基準を記述する場合は、**`rules/` に移せるものは必ず `rules/` に切り出してそこから参照する。**

スキル／エージェントファイル内にルールをインラインで完結させない。

## 「rules/ に移す」の判断基準

以下に当てはまるものは `rules/` に切り出す:

| 該当するもの | 例 |
|------------|-----|
| 他のスキル・エージェントでも適用される可能性がある | 命名規則、ファイル配置 |
| 「常に従うべき不変のガイドライン」の性質を持つ | 禁止事項、必須フォーマット |
| 繰り返し参照される設計上の決定 | ポリシー、品質基準 |

以下は `rules/` に移さなくてよい:

| 該当するもの | 例 |
|------------|-----|
| そのスキル固有の手順・実行ステップ | 「Step 1: ○○する」 |
| スキルの動作ロジック自体 | 入力検証、出力フォーマット指定 |
| 1 回限りのタスク文脈に依存する記述 | — |

## スキル専用コンテンツの `reference/` 分離

`rules/` に移すほど汎用的ではないが、スキル固有のテンプレート・ルール・ガイドラインがインライン記述として長くなる場合は、スキルディレクトリ内の `reference/` サブディレクトリに切り出す。

```
skills/<skill-name>/
├── SKILL.md          ← 参照のみ記載
└── reference/
    └── <content>.md  ← 実体
```

SKILL.md には「`reference/<content>.md` を参照すること」の1行を残す。

## 手順

1. スキル・エージェントに記述しようとするルールが上記「移す」基準に当てはまるか判断する
2. ユニバーサルなルール → `rules/<topic>/` に切り出す（[[directory-rule]] に従う）
3. スキル専用だが長大なテンプレート・ガイドライン → `skills/<name>/reference/` に切り出す
4. スキル・エージェントファイル内には参照（ファイルパス）のみ残す

## スキル作成フローへの反映確認

**`rules/` に新しいルールを追加・更新したら、`skills/create-skill/SKILL.md` にそのルールが反映されているかを確認する。**

確認項目:

- 「参照するルール・テンプレート」テーブルにルールのパスが載っているか
- 手順の中でそのルールに従うよう指示されているか

漏れがあれば create-skill を更新する。

## 参照しても「値」を再掲しない（単一情報源の原則）

`rules/` を参照していても、スキル側に規約の**具体値**（`any 不可`・`70/25/5`・`rounded-lg` 等）を再掲すると二重管理になり、ルール改訂時に黙ってドリフトする。外部化の本質は「参照すること」ではなく「値の唯一の正を `rules/` に保つこと」。

- スキルには**観点名のみ**を索引として残す（例: `命名 / 型 / 定数`、`配色 / 角丸`）。
- 具体値・禁止事項・基準は `rules/` を唯一の正として参照する。
- 「該当ルールを読む」手順の後に値を列挙しない（読了後の再掲は冗長）。
- 同じ値が複数スキルに散っていたら、横展開で全て参照に寄せる。

## 参照例（スキル内の書き方）

```markdown
## ルール

命名規則は [[naming-rule]] (`shared-rules/naming-conventions/naming-rule.md`) に従う。
ファイル配置は [[structure-rule]] (`rules/repository-structure/structure-rule.md`) に従う。
```
