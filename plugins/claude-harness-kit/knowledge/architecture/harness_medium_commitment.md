# ハーネス制御の媒体コミットメント（助言強度のコードはアンチパターン）

**作成日**: 2026-07-20
**カテゴリ**: architecture
**タグ**: [#claude-code, #harness, #hooks, #skills, #design-pattern]

## 概要

「破られたら困るからコードにする」と決めたら、迂回不能な**保証**まで取り切る。コード（スクリプト＋状態ファイル）を用意しながら遵守をモデルの自己判断に委ねる**「助言強度のコード」は最悪の折衷**であり、コードのコスト（可搬性・exit code 解釈・状態管理）を負って強制の便益を得られない。原則は [[harness-rule]]「中間の折衷を避ける」に集約。本メモはその実例。

## 詳細

### 事例: `tdd` スキルの反復上限（3サイクル）

TDD オーケストレーションスキル `tdd` のレビューで、「反復上限はループ制御＝コードに寄せるべき（harness-rule）」との指摘を受け、ガードスクリプト `tdd-cycle.sh`（状態ファイルでサイクル数をカウント、上限で exit 1）を新設した。ただしスキルはこれを「exit code を尊重して停止する」助言強度で呼ぶ設計にした。

次のレビューで、この折衷が複数の実害を生むと判明した:

- **可搬性**: スクリプト参照が相対パス（`bash plugins/.../tdd-cycle.sh`）で、プラグイン配布形態（marketplace install）では cwd 基準で解決できず実行不能。`CLAUDE_PLUGIN_ROOT` が要る。
- **exit code の潰れ**: SKILL が「非0＝上限到達」と一括解釈。起動失敗（127）や引数不備（2）が上限到達（1）と区別されず、**偽 STOP** で最初のサイクル直後に打ち切られる。
- **値の二重持ち**: 上限 `3` がスクリプト（可変: arg > env > default）と SKILL 散文（`n/3` を固定表記）に散在しドリフト。
- **自己申告の再導入**: スクリプトが排除したはずの「n/3」をモデルが出力段で自己申告。
- **保証なきコスト**: コード媒体を選びながら「助言」と保証を放棄。harness-rule がコード化を正当化する便益（迂回不能）を得ていない中間状態。

最終的にスクリプトを撤回し、反復上限を**散文の目安**に戻した（「対話型・可視・中断可能なので強制は過剰」）。3回のレビューを経て、**最初の割り切り（散文の助言）が正しかった**に着地した。

### 教訓

- **媒体は二択に振り切る**: 本当に破られたら困る → hook 等で強制。許容できる → 散文。決定論のためだけにスクリプトを足さない。
- **強制の要否は実行文脈で変わる**: 対話型・メインスレッド可視のスキルは暴走を観測・中断できるため hook 強制は多くの場合過剰。無人の自律ループは観測者がいないためコード強制の価値が高い。同じ「上限」でも文脈で判定が反転する。
- **プラグイン同梱スクリプトの参照は `CLAUDE_PLUGIN_ROOT` を使う**。cwd 依存の相対パスは配布形態で壊れる。
- レビューは指摘の解消だけでなく、**元の設計判断が正しかったか**を問い直す機会になる（過剰対応の巻き戻しも成果）。
