# オーケストレーター型スキルの設計パターン

**作成日**: 2026-06-15
**カテゴリ**: architecture
**タグ**: [#skill, #agent, #orchestration, #delegation]

## 概要

複数の専門スキル・エージェントへ処理を委譲し、結果を束ねて返す「オーケストレーター型スキル」の設計パターン。個々の専門スキル／エージェント（単一責務）はそのまま残し、横断的なユースケースを上位スキルが束ねることで、ロジックを重複させずに「まとめて実行」を実現する。

## 詳細

### パターンの構造

- **専門ユニット**: 単一責務のスキル・エージェント（例: `record-knowledge`, `record-feedback` / `frontend-coder`, `frontend-tester`, `ui-designer`）。
- **オーケストレーター**: 上位のスキル。入力を観点ごとに振り分け、各ユニットの手順・判断基準を踏襲して委譲し、結果を統合する。

### 本リポジトリでの実例

- `record-all`: 会話内容を `record-knowledge`（→ `knowledge/`）と `record-feedback`（→ `rules/`）の両方でまとめて記録する。
- `frontend-code-review`: フロントの変更を `frontend-coder`（規約）/ `frontend-tester`（テスト）/ `ui-designer`（UIデザイン）の3観点で並行レビューし、所見を統合する。

### 設計上のポイント

- オーケストレーターは**ロジックを再実装せず**、委譲先の SKILL.md / エージェント定義の手順・判断基準を「踏襲する」と明示してパスで参照する（ルール外部化と同じ思想。[[skill_rule_externalization_pattern]] を参照）。
- 入力を観点ごとに振り分け、**該当する観点だけ**を起動する（両方該当すれば両方、片方なら片方）。
- 委譲先が独立していれば**並行**で投げてよい（レビュー系）。
- 委譲先の責務境界（指摘のみ／適用まで等）はオーケストレーター側でも維持する。
- 結果は観点ラベル付きで統合し、スキップした観点はその理由を添えて報告する。

### いつ使うか

- 「A も B もまとめてやって」という横断ユースケースが繰り返し発生するとき。
- 既存の単一責務ユニットを壊さず、合成だけで新ユースケースを満たしたいとき。
