## 何の記事か
Claude Code の振る舞いをカスタマイズ（＝ステアリング）する **7 つの方法** を整理し、それぞれ「**いつ命令が読み込まれるか**」「**長いセッション（compaction）を越えて残るか**」「**命令としての強さ（authority）**」「**コンテキストコスト**」の観点で使い分けを示す記事。原則は「命令をコンテキストコストと永続性で整理して配置せよ」。

## 1. 命令を届ける 7 つの方法（概観）
7 手法：**CLAUDE.md ファイル / rules / skills / subagents / hooks / output styles / システムプロンプトへの追記（append）**。

各手法は「読み込みタイミング」「compaction をまたぐ永続性」「命令の強さ」で異なる。コンテキストコストは低（skills・subagents・hooks）〜高（CLAUDE.md ルート・output styles）まで幅がある。

| 手法 | 起動時に読むもの | 本体の読み込み | compaction時 | コスト |
|------|-----------------|---------------|-------------|-------|
| CLAUDE.md（ルート） | 全文 | 常時 | 再読込 | 高 |
| CLAUDE.md（サブディレクトリ） | なし | 当該ディレクトリのファイルを触った時 | 触るまで消える | — |
| rules | 全文（未スコープ時） | — | 再注入 | 中 |
| skills | 名前・説明のみ | 呼び出し時 | 呼ばれたものを予算内で再注入 | 低 |
| subagents | 名前・説明・ツール一覧 | Agent ツール呼び出し時（隔離） | — | 低（呼ぶまでゼロ） |
| hooks | 設定は本文外 | ライフサイクルイベント発火時 | compaction をバイパス | 低 |
| output styles | システムプロンプトに注入 | 常時 | 圧縮されない | 中〜高 |
| append-system-prompt | 起動時に追記 | その 1 回のみ | — | 高め |

## 2. CLAUDE.md ファイル
- **場所**：プロジェクトルートの `CLAUDE.md`、およびサブディレクトリの `app/api/CLAUDE.md` など。共有（リポジトリ）用と個人ローカル用の両方が使える。
- **挙動**：
  - ルート：セッション開始時に読み込まれ、セッション中ずっとコンテキストに残る。compaction 後に再読込される。初回読込後はメモ化されセッション中キャッシュされる。
  - サブディレクトリ：Claude がそのディレクトリのファイルを読んだ時にオンデマンドで読み込まれる。触られるまではコンテキストに入らない。
- **コスト**：高。関連の有無にかかわらず全行がトークンを消費する。
- **推奨用途**：ビルドコマンド、ディレクトリ構成、モノレポ構造、コーディング規約、チームの慣習。
- **ベストプラクティス**：
  - ルートは **200 行未満**に保ち、**オーナーを明示**する。
  - 全チームの指示を 1 ファイルに盛り込まない（遵守率が薄まる）。
  - モノレポではチームごとにサブディレクトリ CLAUDE.md を置き、開発者は `claudeMdExcludes` 設定で無関係なチームの分を除外する。
  - 組織横断の標準は MDM／構成管理で組織全体に配布でき、個人設定では除外できない。

## 3. Rules
- **場所**：`.claude/rules/` 配下のマークダウン。任意の YAML frontmatter に `paths:` を書いてスコープ指定できる。
- **挙動**：
  - 未スコープの rule はセッション開始時に読み込まれ、compaction 時に再注入される（コンテキストコストは中）。
  - path スコープ付きの rule は、一致するファイルを触った時だけ読み込まれ、それ以外はコンテキストに入らない。
  - パス構文例：`"src/api/**"`、`"**/*.handler.ts"`。
- **ベストプラクティス**：
  - 組織横断の制約 → 未スコープの rule。
  - 一部（全部ではない）ファイルに横断的にかかる関心事 → path スコープ付き rule。
  - 例：「全 API ハンドラは処理前に Zod で入力を検証すること」。

## 4. Skills
- **場所**：`.claude/skills/` 配下のフォルダ。`SKILL.md` と補助リソース（スクリプト等）を含む。
- **起動方法**：スラッシュコマンド（例 `/code-review`）、またはシステムプロンプト経由の自動マッチ。
- **挙動**：
  - 起動時は**名前と説明のみ**読み込む。
  - 呼び出された時（手動・自動マッチいずれも）に**本体全文**が読み込まれる。
  - compaction 時は呼ばれた skill を共有予算の範囲で再注入。予算超過時は古い skill から落とす。
  - コンテキストコストは低（本体は呼ばれた時だけ）。
- **推奨用途**：手順型ワークフロー（デプロイのチェックリスト、リリース手順、レビュー手順）。
- 組み込み skill には `/code-review`（差分をレビューするが編集はしない）などがある。カスタム skill も作成可能。

## 5. Subagents
- **場所**：`.claude/agents/` 配下のマークダウン（YAML frontmatter 付き）。frontmatter に name・description、任意で model やツールアクセス設定。本体がサブエージェントのシステムプロンプトになる。
- **挙動**：
  - 起動時は**名前・説明・ツール一覧のみ**読み込む。
  - Agent ツールにプロンプト文字列を渡して呼び出す。
  - **隔離されたコンテキストウィンドウ**で実行され、**最終メッセージ（要約＋メタデータ）だけ**が親セッションに戻る。
  - 呼ぶまでコンテキストコストはゼロ。自身の新しいコンテキストで動く。
  - **最大 5 階層**までネスト可能。「動的ワークフロー」で数十〜数百のバックグラウンドエージェントをオーケストレーションできる。
- **推奨用途**：副次タスク（ディープ検索、ログ解析、依存関係監査）。
- **skill との使い分け**：完全隔離により中間結果でメイン会話を汚さずに済むのが利点。逆に、手順をメインスレッドで進行させてステアリング・可視性を保ちたい場合は skill を使う。

## 6. Hooks
- **登録場所**：`settings.json`、managed policy settings、または skill／agent の frontmatter。
- **発火するライフサイクルイベント**：ファイル編集、ツール呼び出し、セッション開始ほか（`code.claude.com/docs` のインタラクティブなタイムライン参照）。
- **種類**：
  - `command`：決定的にシェルコマンドを実行。
  - `HTTP`：決定的に HTTP エンドポイントを呼ぶ。
  - `mcp_tool`：決定的に MCP ツールを実行。
  - `prompt`：Claude の判断を使う（非決定的）。
  - `agent`：別コンテキストで Claude の判断を使う（非決定的）。
- **挙動**：
  - 特定イベント（`PreToolUse`、`PreCompact` など）で発火。
  - 設定はメイン外にあるためコンテキストコストは低い。
  - 多くは明示設定しない限り出力をメインウィンドウに残さない。
  - `PreToolUse` フックは呼び出しを検査し、**終了コード 2 で拒否**（ブロック）できる。
- **推奨用途**：決定的な自動化（編集後の linter 実行、完了時の Slack 投稿）、ガードレール（`PreToolUse` で特定コマンドをブロック、`PreCompact` で compaction 前にチャット履歴をバックアップ）。managed settings で管理者配布・上書き可能なガードレールを組織横断展開できる。

## 7. Output styles
- **場所**：`.claude/output-styles/` 配下のマークダウン。任意の frontmatter `keep-coding-instructions: true` でデフォルト命令を残せる。
- **挙動**：
  - セッション開始時にシステムプロンプトへ注入され、**圧縮されない**。初回リクエスト後にキャッシュされる（コストは中程度）。
  - カスタムスタイルはデフォルトを置き換える（`keep-coding-instructions: true` を指定しない限り）。
  - **全手法中で最も命令追従の重みが強い**。
- **組み込みスタイル**：Proactive（自律性）、Explanatory（教育モード）、Learning（協働コーディング）。
- **置き換わってしまうデフォルト命令**（カスタムが省略した場合）：変更範囲の絞り方、コメントの付与／省略ルール、セキュリティ懸念の扱い、検証習慣（完了前にテストを走らせる等）。
- **注意**：カスタムスタイルは Claude を「ソフトウェアエンジニア用アシスタント」から「汎用アシスタント」に変えてしまう。まず組み込みスタイルで足りないか確認すること。

## 8. システムプロンプトへの追記（Appending the system prompt）
- **起動方法**：CLI フラグ `append-system-prompt`。その 1 回の起動にのみ適用（セッションをまたいで永続化しない）。プロンプトキャッシュで初回以降のコストを削減。
- **挙動**：
  - 元のシステムプロンプトに**加算**する（Claude の役割は変えない）。
  - コンテキストコストは他手法より高め（入力トークン、場合により出力トークンが増える）。
  - 追記が増えるほど命令追従は逓減する。
- **推奨用途**：特定のコーディング標準、出力フォーマット、ドメイン固有知識。矛盾する指示は避け、短く保つほど効果的。

## 9. カスタマイズのクイックTips（アンチパターンと対処）
| 問題（アンチパターン） | 対処 |
|----------------------|------|
| CLAUDE.md に「毎回 X したら必ず Y」 | `settings.json` の hooks（決定的に実行） |
| CLAUDE.md に「絶対に〜するな」 | hooks（`PreToolUse` 終了コード 2）または managed settings（管理者配布・上書き不可） |
| CLAUDE.md に 30 行の手順 | `.claude/skills/` へ移す（呼ばれた時だけ読み込む） |
| 未スコープの API 専用 rule | `paths:` を付けて `src/api/**` にスコープ |
| プロジェクト CLAUDE.md に個人設定 | ユーザーレベルのファイルへ（全セッションで読まれる） |

**原則の割り当て**：CLAUDE.md＝事実と概要（ビルドコマンド・構成・規約）／skills＝手順（デプロイ手順書・セキュリティチェックリスト）／hooks＝決定的な自動化（linter・Slack 投稿・ブロック）／subagents＝隔離した副次タスク（コンテキスト汚染を防ぐ）。

## 10. はじめかた（Getting started）
- ベストプラクティス：`code.claude.com/docs/en/best-practices#write-an-effective-claude-md` を参照。
- バンドル：skills・subagents・hooks・output styles は **plugin** としてまとめ、チーム／プロジェクトで共有できる。一貫したセットアップをまるごと配布可能。
