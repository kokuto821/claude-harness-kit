## なぜハーネスが必要なのか

AIモデルそのものを賢くするよりも、周囲の「環境（ハーネス）」を整える方がはるかに重要。

- **実績**: LangChainの実験では、モデルは一切変えずハーネスだけを改善することで、ターミナルタスクのベンチマークスコアが **52.8% → 66.5%** へ大幅向上
- **プロンプトとの本質的な違い**:
  - CLAUDE.mdに「本番データベースを削除するな」と書く（プロンプト・アドバイス）→ AIが大量の文脈を処理するうちに無視される危険がある
  - ハーネス（仕組みによる強制）→ 禁止コマンドをシステム的に「完全ブロック」できる

## 5つのレイヤー

本番環境でClaude Codeを安全・確実に動かすための5層のインフラ。

| レイヤー | 役割 | Claude Codeでの実装 |
|---|---|---|
| **1. 記憶 (Memory)** | セッションをまたいでプロジェクトのルールや過去の失敗を覚えさせる | `CLAUDE.md`, `MEMORY.md`, `.claude/commands/` |
| **2. ツール (Tools)** | AIの能力を拡張し、外部システムと連携させる | MCP（Model Context Protocol）サーバー |
| **3. 権限 (Permissions)** | AIが触っていいファイルや実行できるコマンドを制限する | `settings.json` の Allow / Deny リスト |
| **4. フック (Hooks)** | AIがツールを使う直前・直後に自動チェックをかける | `PreToolUse` / `PostToolUse` フック |
| **5. 可観測性 (Observability)** | AIが何をしたか・いくらかかったかを人間が見えるようにする | セッションログ、コスト追跡、アクション監査 |

## 構築の「正しい順番」

多くの開発者はまずAIにツール（MCP）をたくさん与えてしまいがちだが、**「能力を与える前に、ガードレールを先につくる」**順番が重要。

```
1. 記憶（CLAUDE.md）  → 基本ルールを定義する
       ↓
4. フック（Hooks）    → 危険な操作を自動ブロックする仕組みを先に作る
       ↓
2. ツール（MCP）      → 追加する（プロジェクトごとに2〜3個がベスト、5個以上はノイズ）
       ↓
3. 権限（Permissions）→ 安全な境界線を引く
       ↓
5. 可観測性           → ログやコストを追跡する
```

## 8つのディープダイブ

### 1. 動的な記憶の追加（MEMORY.md の活用）

Claude Codeはセッションごとに記憶がリセットされる。

- **CLAUDE.md**（静的ルール）: 基本的なプロジェクトルールを記載。**40〜60行に抑えるのがベスト**
- **MEMORY.md**（動的な履歴）: 開発の歴史・先週ハマったバグの教訓などを蓄積

### 2. 「失敗ログ」としてのルール作成

理想論の指示を書くのではなく、AIが過去に実際にやらかした「リアルな失敗」をベースに制約ルールをアップデートしていく。

### 3. ランタイム・フックの設計

4つのフックハンドラーを使い分ける：

| ハンドラー | 用途 |
|---|---|
| Deny（拒否） | 危険なコマンドをブロック |
| Log（記録） | 操作の証跡を残す |
| Transform（変換） | 出力を安全な形式に変換 |
| Approve（承認） | 人間のチェックを挟む |

### 4. 自己検証ループ（Self-Verification Loop）

AIがタスク完了と判断した際に、自動でチェックリストを走らせてコード品質を2〜3倍に引き上げる **`/done` コマンド**の実装。

### 5. 制約のパラドックス（The Constraint Paradox）

> 「AIの自由度を減らす（制約をきつくする）ほど、生成されるコードの質が上がる」

制約が少ないと、AIは最短経路を選んで品質を犠牲にするが、適切な制約があると本質的な解決策を探す。

### 6. シニアエンジニアの役割の変化

| 従来 | これから |
|---|---|
| 自分でコードを書くこと | AIエージェントが安全に自律駆動できる「ハーネス（環境）」を設計すること |

### 7〜8. その他のベストプラクティス

- MCPツールは多すぎると逆効果。プロジェクトごとに **2〜3個**に絞る
- `.claude/commands/` にカスタムコマンドを登録し、繰り返し作業を自動化

## 今日からできる3つのクイック・ウィン

大規模な構築は不要。まず30分以内でできる以下の3つから始める：

| アクション | 時間 | 内容 |
|---|---|---|
| **MEMORY.md の作成** | 5分 | 過去のアーキテクチャ決定事項・教訓をまとめたインデックスファイルを作る |
| **PreToolUse フックの追加** | 15分 | 1つだけでいいので、危険なファイル操作やコマンドを遮断するスクリプトを仕込む |
| **コスト意識の有効化** | 10分 | `~/.claude/projects/` を確認し、セッションごとの消費トークン・コストを把握する習慣をつける |
